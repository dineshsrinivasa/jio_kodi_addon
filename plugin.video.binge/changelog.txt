Changelog
========

v1.0.12 (2026-09-07)
--------------------
[fixed] OTT browse/search now work: the Binge web app sends device headers (anonymousid, deviceid,
        deviceToken, deviceType, deviceName, apiVersion, x-authenticated-userid, subscriberId, baId)
        on every API call - these are now included, fixing the homescreen "Cannot read properties of
        undefined (reading 'startsWith')" server error and the search 404s
[fixed] Homescreen/rail endpoint paths corrected to the exact bundle routes (page/{page} without the
        /BINGE_ANYWHERE suffix, rail via homescreen-client/api/v3/rail with rule=VRPRIMERAILFILTER)
[fixed] Live channel detail now sends the full session auth (bearer accessToken, x-subscriber-id,
        x-subscriber-name, profileid, anonymousid, deviceid) so kong no longer answers "Blocked"
[fixed] Empty OTT sections (search / browse / rails / seasons) show an explanatory item instead of
        raising codequick's "No items found" RuntimeError
[added] session now stores deviceToken + baId from the login response for richer headers

v1.0.11 (2026-09-07)
--------------------
[fixed] Channel list: fetch now pulls the full ~800-channel catalogue in a single request (page size 1000)
        instead of 8 slow pages - the Zee TV / All Channels menus previously exceeded Kodi's addon-execution
        budget and were killed (script didn't stop in 5 seconds)
[fixed] OTT menu no longer crashes: Route.ref() has no params argument in codequick - params are passed via
        Listitem.from_dict(**{"params": {...}}) - fixed ott_browse/ott_rail/ott_item/ott_season call sites
[added] OTT menu restructured Kannada-first: dedicated "Kannada (Movies + Series)" section, plus Zee5 and
        JioHotstar sections, next to Search / Browse-by / Top Picks
[added] Kodi house-style note: partner OTT playback needs each partner's proprietary DRM API (JioHotstar
        deep-links out to the app), so titles remain browse-only for now

v1.0.10 (2026-09-07)
--------------------
[fixed] Login: the successful login response carries the session under "userAuthenticateToken" (not accessToken),
        and codequick's Settings/Script classes have no set_string/open_settings attributes - so the new session
        was never saved (login actually succeeded server-side) and in-add-on login crashed. Token extraction is
        now case-insensitive + userAuthenticateToken-aware; Settings.set_string -> Script.setting[...];
        Script.open_settings -> Addon.OpenSettings builtin.
        Verified: update/exist/user returns code 0 "Logged in successfully." with baId=1010094715,
        bingeSubscriberId=2075157065, profileId=VR_63... for the non-DTH account.

v1.0.9 (2026-09-07)
[fixed] Login: subscriber/details call was missing the platform: BINGE_ANYWHERE header -> server returned code 400
        "Missing request head", so the account baId was never fetched -> "Null or empty ba id" on update/exist/user.
        Header added; baId + dthStatus + subscriberId now logged for diagnosis.

v1.0.8 (2026-09-07)
-------------------
[fixed] Login: already-registered accounts (validateOTP returns firstTimeLogin=false) now use "update existing user"
        (api/v3/update/exist/user) instead of "create new user" - create returned HTTP 500 for existing non-DTH accounts
[added] subscriber/details response now logged so the create-vs-update decision is visible

v1.0.7 (2026-09-07)
-------------------
[fixed] Login rewritten for NON-DTH (Binge-only) accounts - the old web/SID flow (tm.tapi) refused RMN-only users (code 10005/1003)
[added] Binge-mobile web-platform login flow (matches the tataplaybinge.com app):
        register guest device -> anonymousId/deviceId -> generateOTP -> validateOTP -> create/update user -> session
        Flow: RMN -> send OTP -> verify ONLY. No 10-digit subscriber ID required.
        OTP: POST binge-mobile-services/pub/api/v1/user/authentication/generateOTP
        Verify: POST .../authentication/validateOTP
        Session: POST binge-mobile-services/api/v3/create/new/user (or /update/exist/user for DTH)
        Source: reverse-engineered from the public www.tataplaybinge.com web app
