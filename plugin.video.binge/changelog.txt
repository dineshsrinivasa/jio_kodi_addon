Changelog
=========

v1.0.9 (2026-09-07)
-------------------
[fixed] Login: subscriber/details call was missing the platform: BINGE_ANYWHERE header -> server returned code 400
        "Missing request head", so the account baId was never fetched -> "Null or empty ba id" on update/exist/user.
        Header added; baId + dthStatus + subscriberId now logged for diagnosis.

v1.0.8 (2026-09-07)
-------------------
[fixed] Login: already-registered accounts (validateOTP returns firstTimeLogin=false) now use "update existing user"
        (api/v3/update/exist/user) instead of "create new user" - create returned HTTP 500 for existing non-DTH accounts
[added] subscriber/details response now logged so the create-vs-update decision is visible

v1.0.7 (2026-09-07)
-------------------
[fixed] Login rewritten for NON-DTH (Binge-only) accounts - the old web/SID flow (tm.tapi) refused RMN-only users (code 10005/1003)
[added] Binge-mobile web-platform login flow (matches the tataplaybinge.com app):
        register guest device -> anonymousId/deviceId -> generateOTP -> validateOTP -> create/update user -> session
        Flow: RMN -> send OTP -> verify ONLY. No 10-digit subscriber ID required.
        OTP: POST binge-mobile-services/pub/api/v1/user/authentication/generateOTP
        Verify: POST .../authentication/validateOTP
        Session: POST binge-mobile-services/api/v3/create/new/user (or /update/exist/user for DTH)
        Source: reverse-engineered from the public www.tataplaybinge.com web app

v1.0.6 (2026-09-07)
-------------------
[fixed] Login/OTP APIs updated to the current Tata Play web platform (tm.tapi.videoready.tv) - OTP was returning 404
        OTP: POST .../v2/generate/otp | SID lookup: POST .../v2/subscriberLookup | Login: POST .../v3/login/ott

v1.0.5 (2026-09-07)
-------------------
[fixed] CRITICAL: "Script.run() AttributeError" - addon entry now calls codequick's run correctly (matched jiotv)

v1.0.4 (2026-09-07)
